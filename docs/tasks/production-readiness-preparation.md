# Production readiness — preparation fixes

## Intent and acceptance

A production-readiness audit (`docs/production-readiness.html`, generated by the product-discovery production-readiness skill) found three local gaps before a first deployment for AIPH3 course participants. The hosting provider is not chosen yet; nothing is deployed.

1. **Unexpected render error.** The app had no React error boundary: an unexpected exception while rendering left a blank page. Add a recovery screen in Polish that keeps the data in the browser, offers a retry, and leads to data settings (export/import/reset). A route-level boundary keeps the shell/navigation; an outer boundary covers a crash of the shell itself. Navigating to another route clears the error.
2. **Post-publication check.** Document a short smoke plan: target address, main journey, hash deep links, external requests, and the rollback condition.
3. **Recovery plan.** Document a runbook: owner (Tom), diagnosis, returning to the previous build, participant data recovery through export/import/reset, and participant communication. Provider-specific steps stay open until hosting is chosen.

Also exclude the generated report from Prettier (it is rendered by the skill and must not be hand-edited).

Acceptance: `./scripts/verify` passes including Playwright; a focused browser regression proves the error screen, retry and recovery link; desktop/mobile/keyboard check of the new screen; FEATURES.md updated.

## Design-system scope

Route: any route inside `Shell` (fallback replaces the outlet only). Source family: C17 Empty/recovery (contextual heading, reason, recovery action). Host recipe reused as-is from `NotFound`: `prototype-section`, H1, paragraph, `buttonVariants()` primary action plus an outline action. No new styles, tokens or components beyond the boundary itself. Kit unchanged.
